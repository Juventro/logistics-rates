# Аналитика и прогнозирование ставок грузоперевозок

Решение тестового задания: пакетная загрузка, хранилище PostgreSQL 17, рыночные витрины и прогноз тарифа за рейс. Исходное задание сохранено в [ASSIGNMENT.md](ASSIGNMENT.md), исходные DDL и генератор в `sql/schema.sql` и `sql/synthetic.sql` не изменены.

## Запуск

Нужны Docker Engine / Docker Desktop и Compose. Из корня репозитория:

```bash
docker-compose up
```

Альтернативное написание для Compose v2: `docker compose up --build`.
Без дополнительных настроек создаются 300 000 сделок, загружаются слои, обучается CatBoost и записываются прогнозы. После сообщения `pipeline_complete` контейнер `pipeline` завершится с кодом 0, PostgreSQL продолжит работать. Ошибка любого этапа завершает задание ненулевым кодом.

Настройки можно переопределить через `.env` по примеру `.env.example`. Значения по умолчанию предназначены для локального синтетического стенда. Порт PostgreSQL опубликован только на `127.0.0.1:55432`. Не используйте демонстрационный пароль во внешней среде. Пароль с зарезервированными URI-символами в `DATABASE_URL` должен быть URL-кодирован.

```bash
docker compose logs -f pipeline
docker compose exec db psql -U postgres -d deals_bigdata
docker compose cp pipeline:/app/artifacts ./artifacts
```

В `artifacts` сохраняются модель `.cbm`, `metrics.json` и `run_summary.json`. Каталог хранится в отдельном Docker volume. Повторный `up` использует уже созданный источник; изменение `N_PRICES` не перегенерирует существующую БД. Для нового синтетического стенда: `docker compose down -v`, затем повторный запуск. Эта команда удаляет данные стенда и модели.

## Устройство

```text
исходные SQL -> raw -> транзакционная очистка -> core -> mart.market_corridor
                                                |
                                                +-> признаки -> CatBoost -> mart.ml_price_predictions
```

- `raw`: исходная операционная модель и синтетические данные.
- `core.prices`: одна валидная запись на исходную цену, сумма в RUB без НДС.
- `core.cities`: одна запись на `gc_id`, выбирается минимальный исходный `id`; регион извлекается из части полного имени после запятой.
- `core.price_bodies`: уникальная пара `price_id × body_group`. Отсутствующая связь с типами кузова заменяется исходным `prices.body_type`, затем группой `Не указан`.
- `core.price_months`: исходные даты из `price_dates`; долгосрочная заявка сохраняет несколько месячных наблюдений.
- `core.dq_quarantine_prices`: исходная строка, все найденные причины отказа и дата загрузки.
- `mart.market_corridor`: месяц × отправление × назначение × группа кузова × весовая категория.
- `mart.ml_price_predictions`: цена × группа кузова × имя модели.

Одна сделка может принадлежать разным группам кузова. Поэтому суммы количества сделок по разным группам не являются числом уникальных сделок во всём источнике. Внутри одной месячной ячейки одна цена учитывается строго один раз. Объёмная категория сохранена в core и ML-признаках, но не расширяет зерно рыночной витрины.

## Очистка и валюты

Проверяются положительная цена и дистанция, неотрицательные вес и объём, наличие обоих городов и поддерживаемая валюта. Для RUB дополнительно отбрасываются цены `<= 1000`. Проверяются также NaN/Infinity. Отрицательные параметры не заменяются нулями. Совпадение городов само по себе не считается ошибкой.

RUB имеет курс 1. USD/EUR конвертируются по точному `nearest_rate_date`, сохранённому в источнике; при дублирующемся курсе выбирается минимальный `exchange_rates.id`. Отсутствующая дата, отсутствующий или невалидный курс ведут в карантин. Fallback на дату погрузки не применяется. Производственный алгоритм заполнения `nearest_rate_date` описан в приложениях; в этом решении поле используется как входное значение, а не восстанавливается заново. Денежная сумма после конвертации округляется до копеек.

Пропущенная весовая категория определяется после округления веса до 0,1 т: `G20T >= 30`, `FTL >= 10`, `10T >= 5`, `5T >= 2.5`, `L5T >= 0.5`, иначе `OTH`. Объёмная: `FTL` при `0 < volume <= 120`, иначе `OTH`. Заполненные исходные категории сохраняются.

`outlier_mark` сохраняется в core и используется для фильтрации исторического рынка и обучения. Флаг не пересчитывается. Свежие сделки 26.10.2026 после ночного джоба ещё могут содержать неразмеченные аномалии: `false` не гарантирует отсутствие выброса. Это ограничение исходного снимка.

## Витрины и даты

Снимок фиксирован: `as_of=2026-10-26`; системная дата не участвует в расчётах. Месяц рынка определяется по `price_dates.price_date`, а не по `loading_date`. Будущие месяцы в рынок не включаются.

Для рынка используются только факты типов `1,2,3,4,5,9`, прямые маршруты и строки без `outlier_mark`. Процентили считаются точно через `percentile_cont`, показатели за километр из нормализованной цены в RUB. Перевозчики считаются по уникальным `organization_id` только типов `3,9`. Коэффициент вариации использует `stddev_samp`, при числе наблюдений менее двух возвращает NULL.

MoM/YoY сопоставляют календарные ячейки с предыдущим месяцем / тем же месяцем прошлого года. Отсутствующий календарный период даёт NULL. Свежесть для `HIGH` измеряется от `as_of` до максимальной фактической `price_dates.price_date` в ячейке, а не до времени запуска загрузки. Порог HIGH: 30 сделок, 5 перевозчиков, свежесть не более 30 дней; MEDIUM: не менее 10 сделок; иначе LOW_DATA.

```sql
SELECT month,body_group,weight_category,p25_trip,median_trip,p75_trip,
       median_km,trips_count,carriers_count,mom_pct,yoy_pct,reliability_level
FROM mart.market_corridor
WHERE loading_city_gcid=1001 AND unloading_city_gcid=1003
ORDER BY month DESC,body_group,weight_category;

SELECT reason,count(*)
FROM core.dq_quarantine_prices,unnest(reasons) AS reason
GROUP BY reason ORDER BY count(*) DESC;

SELECT loading_date,actual_price_rub,predicted_price_rub,ape_pct
FROM mart.ml_price_predictions ORDER BY loading_date DESC LIMIT 20;
```

## Повторные запуски и backfill

Обе границы окна загрузки включительны, окно задаётся по `loading_date`.

```bash
docker compose run --rm pipeline python -m etl.pipeline --start-date 2026-10-05 --end-date 2026-10-26
docker compose run --rm pipeline python -m tests.check_repeatability
```

Очистка окна, карантин, мосты и пересчёт рынка выполняются в одной транзакции. Старые записи окна удаляются, затем вставляется актуальное состояние, включая исправленные и удалённые исходные записи. Advisory lock исключает одновременную запись пайплайнов. Пересчёт рынка полный: при 300 000 строк это простой способ корректно обновить все затронутые месяцы и сравнения. Инициализация источника тоже атомарна и повторно данные не генерирует.

`--skip-ml` позволяет отдельно выполнить загрузку; прогнозы для перезагруженных цен удалятся каскадно и будут восстановлены следующим полным скорингом. Изменение бизнес-ключей / справочников или перенос `loading_date` за границы окна требует backfill, покрывающего старую и новую даты; полноценного CDC в этом прототипе нет. Обновление справочника городов полное, старые сделки вне окна автоматически не перевалидируются.

Проверка повторяемости сравнивает количество и хеш содержимого core, карантина, рынка и прогнозов после полного и частичного запуска. Только технический `scored_at` исключён из сравнения.

## ML

CatBoost выбран для нелинейной регрессии с категориальными признаками. Параметры фиксированы до оценки test: 300 итераций, глубина 6, learning rate 0.08, seed 42, 2 потока. Test не используется для early stopping или подбора параметров.

Разбиение по `loading_date`:

- train: `[2026-07-26, 2026-10-05)`;
- test: `[2026-10-05, 2026-10-26]`;
- будущие заявки: после 26.10.2026.

Признаки задаются белым списком: расстояние, вес, объём, координаты и раздельные регионы отправления/назначения, группа кузова и категории груза, год, sin/cos месяца, дня недели и дня года. Отсутствующие категории заменяются константой, числовые пропуски обрабатывает CatBoost; статистики по test не вычисляются.

Цена, её производные, маржа, групповые статистики и `price_group_id`, идентификатор сделки и `outlier_mark` не входят в признаки. Таргет - `price_rub` без логарифмирования. Выборка ограничена прямыми фактами типов `1,2,3,4,5,9`; для исторической части применяется входной outlier-флаг. Для будущего скоринга берутся те же типы источников. Будущие `actual_price_rub`, `abs_error_rub`, `ape_pct` всегда NULL, даже при заполненной исходной цене.

R², MAPE (%), RMSE и MAE (руб.) записываются в JSON и структурированный лог. Результаты выполненного прогона см. в [reports/metrics.json](reports/metrics.json) и [reports/run_summary.json](reports/run_summary.json). Референсные метрики из R&D не используются как обещание качества или проходной порог.

## Проверки

```bash
docker compose exec db createdb -U postgres deals_bigdata_test
docker compose run --rm -e TEST_DATABASE_URL=postgresql://postgres:local_demo_only@db:5432/deals_bigdata_test pipeline python -m pytest -q
```

Интеграционные тесты отказываются очищать базу, имя которой не заканчивается на `_test`. Без TEST_DATABASE_URL запускаются только независимые проверки Python. Тесты покрывают границы DQ, курс по сохранённой дате, округление категорий, дубли справочников и кузовов, месячное зерно, перцентили, пропуски календарных месяцев, откат транзакции, повторную инициализацию, защиту признаков от утечек и NULL для будущего факта.

GitHub Actions собирает контейнер, выполняет весь конвейер на PostgreSQL 17, тесты и сравнение полных / частичных повторных прогонов. Логи и модель доступны в артефактах запуска.

## Границы решения

Реализована обязательная часть. Airflow, Superset и ClickHouse не добавлены: для воспроизводимого локального прототипа достаточно одного Python-процесса и PostgreSQL. HTML в attachments остаётся продуктовым демо. Нет API, онлайн-инференса, пересчёта выбросов и подключения к внешнему сервису курсов: используются переданные справочники снимка.
